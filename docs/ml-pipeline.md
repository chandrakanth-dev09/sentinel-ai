# Machine Learning Pipeline

## Model and feature set

SentinelAI uses an unsupervised scikit-learn `IsolationForest`. The model is fitted only on healthy training observations. Features are CPU, memory, and disk utilization; response time; error rate; request rate; database connections; and network traffic. In the current ingestion schema, `request_rate` is the ingested request count per sample because metric intervals are not yet a separate field.

The pipeline replaces positive/negative infinity with missing values and applies a median `SimpleImputer`. A scaler is intentionally omitted: Isolation Forest makes tree-split decisions and is not distance-based, so scaling these differently measured features is not required for this estimator.

## Dataset and labels

The first training/evaluation source is a reproducible synthetic monitoring dataset generated by `app.ml.synthetic_data`. Healthy observations use seeded, documented distributions. Evaluation anomalies come from explicit database-failure, memory-leak, API-latency, and cascading-failure transformations. Labels are derived from the scenario used to construct each row; labels are never randomly assigned. The model training set contains healthy observations only.

This dataset is a development fixture, not a public benchmark or a substitute for telemetry from a target production system. Its controlled scenario ranges are separable from the healthy distributions and therefore can yield much stronger metrics than real operations. Generalization and incident-level detection latency have not been established. A future benchmark should add a documented public dataset such as NAB or Yahoo S5 with a time-aware split and carefully aligned labels.

## Training, persistence, and evaluation

Run from the backend directory:

```powershell
.\.venv\Scripts\python.exe -m app.ml.train
```

The command uses a fixed random seed by default, trains on healthy rows, sets a score threshold from the lower tail of training decision scores, evaluates on a separate seeded set, and saves a versioned Joblib bundle. Override `MODEL_PATH` or pass `--output` to choose another artifact location.

Evaluation reports precision, recall, F1, false-positive rate, scenario-specific recall, and mean per-row inference latency measured locally during vectorized evaluation. The latency figure is not time-to-detect an incident and is not a production SLO. The `model-status` API returns metrics read from the generated artifact; no scores are hardcoded.

The model API predicts from the latest stored metric for a service (or a requested metric ID), writes each result to `anomaly_events`, and returns all input feature values with robust deviations from the healthy training medians/IQRs. Those deviations are descriptive evidence, not causal attributions or calibrated probabilities.
